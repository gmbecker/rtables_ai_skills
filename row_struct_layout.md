# `rtables` Row Faceting Structure Programming Skill

This skill provides a complete engineering guide and archetype catalog for translating table shells into **row faceting layouts** in `rtables`.

> [!IMPORTANT]
> **Strict Scope & Tabulation Model Invariants**
> - **Column Structure Exclusivity**: Column structure is defined exclusively by `split_cols_by*` calls and is **orthogonal** to row structure. All examples in this skill omit column splitting (rendering the single default `all obs` column) to isolate row structure.
> - **Row Faceting Structure**: Row faceting (up to, but not including, individual leaf rows) is implemented via zero or more calls to the **`split_rows_by*`** family of functions (`split_rows_by`, `split_rows_by_cuts`, `split_rows_by_cutfun`, `split_rows_by_quartiles`, `split_rows_by_multivar`).
> - **Individual Leaf Rows**: Row faceting never creates leaf rows by itself; every row-faceting branch **must** terminate with one or more calls to **`analyze()`**.
> - **Marginal Group Summary Rows**: Facet labels are converted into marginal group summary rows (content rows) via a single call to **`summarize_row_groups()`** placed **directly after** the relevant `split_rows_by*` call (or before the first split for a root-level summary row).
> - **When to Combine `child_labels = "visible"` with `summarize_row_groups()`**: Setting `child_labels = "visible"` on `split_rows_by()` followed by `summarize_row_groups()` is **only** used when the row(s) generated by `summarize_row_groups()` do **not** act in the same capacity as the default label row for that facet (e.g., when `summarize_row_groups()` emits multiple summary rows indented beneath the facet label).
> - **Cell Content Agnostic**: Choosing or writing statistical `afun` and `cfun` functions is covered in separate skills. When prototyping or verifying row structure, always use lightweight dummy functions (`dummy_one_row` and `dummy_n_rows_factory(n)`).

## 1. Prototyping Harness: Shared Dummy Functions

When translating or testing a row layout against a shell, use these two dummy functions as placeholders for `cfun` and `afun` so you can verify the exact row hierarchy, indentation, and label visibility independently of cell statistics:

```r
library(rtables)

# Emits 1 row (for 1-row analyze() or single-line summarize_row_groups() replacing the facet label)
dummy_one_row <- function(x, label_str = NULL, labelstr = label_str, ...) {
  if (is.null(label_str) && !is.null(labelstr) && nzchar(labelstr)) label_str <- labelstr
  label <- if (is.null(label_str) || !nzchar(label_str)) "label" else label_str
  rcell("-", format = "xx", label = label)
}

# Emits n rows ("a", "b", ...) (for multi-row analyze() or multi-row summarize_row_groups())
dummy_n_rows_factory <- function(n) {
  function(x, label_str = NULL, labelstr = label_str, ...) {
    labs <- if (n <= 26) letters[seq_len(n)] else paste0("r", seq_len(n))
    cells <- lapply(seq_len(n), function(i) rcell("-", format = "xx", label = labs[i]))
    names(cells) <- labs
    in_rows(.list = cells, .labels = labs)
  }
}
```

## 2. Translating a Table Shell's Row Structure into a Layout

To translate a visual table shell into `rtables` row layout instructions, inspect the **row labels**, their **indentation levels**, and whether **group header lines carry cell values**:

### Step 1: Identify Top-Level Sections vs. Nested Hierarchies
Determine the **scope** of each row label (which descendant rows it applies to):
1. **Unfaceted Root Analysis Section**:
   If a top-level label (e.g., `"All Patients"`) sits directly above individual analysis rows (`"Yes"`, `"No"`) and applies to the entire dataset without partitioning by a grouping variable, you do **not** need `split_rows_by()`. Use a single `analyze()` call with a visible variable label:
   ```r
   basic_table() |>
     analyze("BMEASIFL", afun = dummy_n_rows_factory(2),
             var_labels = "All Patients", show_labels = "visible")
   ```
2. **Nested Faceting Section**:
   If an outer label (e.g., `"Asian"`, `"Black"`, `"White"` from `RACE`) scopes over intermediate labels (`"Male"`, `"Female"` from `SEX`), which in turn scope over leaf rows (`"Yes"`, `"No"` from `BMEASIFL`), chain `split_rows_by()` calls from outermost to innermost, terminating with `analyze()`:
   ```r
   basic_table() |>
     split_rows_by("RACE") |>
     split_rows_by("SEX", split_fun = keep_split_levels(c("Male", "Female"))) |>
     analyze("BMEASIFL", afun = dummy_n_rows_factory(2))
   ```

### Step 2: Distinguish Pure Label Rows from Marginal Group Summary Rows
Inspect the cells to the right of each group header label in the shell:
```text
Asian              -            -     <-- Pure facet label row (empty cells)
  Male             xx           xx    <-- Marginal group summary row (non-empty cells)
    Yes        xx (xx.x%)   xx (xx.x%) <-- Individual analysis leaf rows
    No         xx (xx.x%)   xx (xx.x%)
```
- **Pure Facet Label Row (`Asian`)**: Generated automatically by `split_rows_by("RACE")` (where `child_labels = "default"` resolves to `"visible"` when no `summarize_row_groups()` follows).
- **Marginal Group Summary Row (`Male   xx   xx`)**: Generated by placing `summarize_row_groups()` **immediately after** `split_rows_by("SEX")`. Because `child_labels = "default"`, the content row returned by `summarize_row_groups()` **replaces** the plain `"Male"` label row (inheriting its label via `labelstr`):
  ```r
  basic_table() |>
    split_rows_by("RACE") |>
    split_rows_by("SEX", split_fun = keep_split_levels(c("Male", "Female"))) |>
    summarize_row_groups(cfun = dummy_one_row) |>
    analyze("BMEASIFL", afun = dummy_n_rows_factory(2))
  ```

### Step 3: Stack Sequential Sections
Combine consecutive row sections into a single pipeline.
- **Crucial Rule**: Any `split_rows_by*` call that directly follows an `analyze()` call **automatically defaults to `nested = FALSE`** (starting a new top-level section at the root of the row tree).
```r
basic_table() |>
  # Section 1: Root analysis for All Patients
  analyze("BMEASIFL", afun = dummy_n_rows_factory(2),
          var_labels = "All Patients", show_labels = "visible") |>
  # Section 2: Automatically un-nested (top-level) RACE -> SEX -> BMEASIFL hierarchy
  split_rows_by("RACE") |>
  split_rows_by("SEX", split_fun = keep_split_levels(c("Male", "Female"))) |>
  summarize_row_groups(cfun = dummy_one_row) |>
  analyze("BMEASIFL", afun = dummy_n_rows_factory(2))
```

## 3. Controlling Row Nesting, Multi-Section Layouts, and `at_sibling` Anchoring

### 3.1 Default Nesting vs. `nested = FALSE`
| Sequence of Layout Calls | Default Behavior (`nested = TRUE`) | Effect of `nested = FALSE` on Second Call |
| :--- | :--- | :--- |
| `split_rows_by("A") \|> split_rows_by("B")` | `B` nests **inside** every level of `A` ($A \times B$ hierarchy). |*(Invalid without terminating `A` with `analyze()` first)* |
| `split_rows_by("A") \|> analyze("X") \|> analyze("Y")` | `X` and `Y` are bundled together as consecutive leaf tables **inside** every level of `A`. | `analyze("Y", nested = FALSE)` places `Y` at the **root** level after the entire `A` section finishes. |
| `analyze("X") \|> split_rows_by("B")` | `split_rows_by` after `analyze` **always defaults to `nested = FALSE`** (places `B` as a new root section after `X`). | Explicit `nested = FALSE` has the same root-level behavior, making section boundaries visually clear in code. |

### 3.2 Intermediate Nesting with `at_sibling` (`rtables >= 0.7.0`)
In a deep hierarchy (`A -> B -> C -> D -> analyze("X")`), you often need to place an additional `analyze()` or `split_rows_by*` neither at the deepest leaf (`D`) nor all the way at the root (`nested = FALSE`), but at an **intermediate level** as a direct sibling to `B` or `C`.

Pass **`at_sibling = "<anchor_name>"`** to `split_rows_by*` or `analyze()`:
```r
basic_table() |>
  split_rows_by("RACE", split_fun = keep_split_levels(c("ASIAN", "WHITE"))) |>
  split_rows_by("STRATA1", split_fun = keep_split_levels(c("A", "B"))) |>
  split_rows_by("SEX", split_fun = keep_split_levels(c("F", "M"))) |>
  analyze("AGE", afun = dummy_one_row) |>
  # Placed inside each RACE facet as a sibling to the STRATA1 subtable:
  analyze("BMRKR2", at_sibling = "STRATA1", show_labels = "visible", afun = dummy_one_row)
```
Rendered structure per `RACE` level:
```text
ASIAN
  STRATA1
    A
      F
        label   -
      M
        label   -
    B
      F
        label   -
      M
        label   -
  BMRKR2
    label       -
```

#### Rules for `at_sibling` Anchor Resolution & Placement Order
1. **Inspecting Eligible Anchors**: Call `get_row_anchor_list(lyt)` at any point to inspect the currently eligible anchor names along the active right-hand horizon of the layout tree.
2. **Inside-Out Placement Order (Deepest Anchor First)**:
   When anchoring multiple sibling elements to *different* ancestor levels within the same branch, you **must** place them in order from **most deeply nested anchor point to least deeply nested anchor point**.
   - Why: Anchoring an element to an outer split (e.g., `STRATA2`) diverts the active branch horizon to the newly placed sibling, making deeper splits inside `STRATA2` (such as `RACE`) no longer eligible for subsequent `at_sibling` calls.
   ```r
   # CORRECT (deepest anchor "RACE" first, then outer anchor "STRATA2"):
   basic_table() |>
     split_rows_by("STRATA1") |>
     split_rows_by("STRATA2") |>
     split_rows_by("RACE") |>
     split_rows_by("SEX") |>
     analyze("AGE", afun = dummy_one_row) |>
     analyze("BMRKR2", at_sibling = "RACE", show_labels = "visible", afun = dummy_one_row) |>
     analyze("BMRKR1", at_sibling = "STRATA2", show_labels = "visible", afun = dummy_one_row)
   ```
3. **Disambiguating Anchor Names with `table_names`**:
   If the same variable is split or analyzed multiple times, assign unique `table_names = "..."` on each `split_rows_by*` or `analyze()` call and reference that `table_names` string in `at_sibling`.

### 3.3 Designing Multi-Section Row Layouts to Support Subgroup Variants
Suppose a core table has 3 sections: (1) Overall `AGE`, (2) `AGE` by `RACE`, and (3) `AGE` by `SEX`.
- **Anti-Pattern (Relying on default `nested = FALSE` after `analyze`)**:
  If you write `analyze("AGE") |> split_rows_by("RACE") |> analyze("AGE") |> split_rows_by("SEX") |> analyze("AGE")` and later prepend `split_rows_by("STRATA1")` at the top to create a subgroup table, only the first `analyze("AGE")` nests inside `STRATA1`; `RACE` and `SEX` jump all the way out to the root level!
- **Best Practice (Anchor Subsequent Sections to the First Section via `at_sibling`)**:
  Anchor `RACE` and `SEX` to `"AGE"` (`at_sibling = "AGE"`). In a standalone table, this renders at the top level; when preceded by `split_rows_by("STRATA1")` (with or without `page_by = TRUE`), the **entire** 3-section structure repeats cleanly inside each stratum:
  ```r
  basic_table() |>
    split_rows_by("STRATA1", split_fun = keep_split_levels(c("A", "B"))) |> # Optional outer subgroup wrapper
    analyze("AGE", afun = dummy_one_row) |>
    split_rows_by("RACE", split_fun = keep_split_levels(c("ASIAN", "BLACK OR AFRICAN AMERICAN")),
                  at_sibling = "AGE") |>
    analyze("AGE", afun = dummy_one_row) |>
    split_rows_by("SEX", split_fun = keep_split_levels(c("F", "M")),
                  at_sibling = "AGE") |>
    analyze("AGE", afun = dummy_one_row)
  ```

## 4. Label Visibility, Placement, Indentation & Section Dividers

Row labels are controlled by three distinct parameters across two levels of the API:

### 4.1 The Three Label Control Parameters

| Parameter | Where Used | Allowed Values | What It Controls |
| :--- | :--- | :--- | :--- |
| **`label_pos`** | `split_rows_by*()` | `"hidden"` *(default)*, `"visible"`, `"topleft"` | **The split variable's own name/label** (`split_label`, e.g., `"Sex"` or `"System Organ Class"`):<br>• `"hidden"`: Not shown.<br>• `"visible"`: Shown as a dedicated header row above its level facets (and automatically shown when `at_sibling` anchors a sibling next to the split).<br>• `"topleft"`: Placed in the top-left corner area above the table's row label column (indented according to nesting depth). |
| **`child_labels`** | `split_rows_by*()` | `"default"` *(default)*, `"visible"`, `"hidden"` | **The individual facet level labels** (e.g., `"F"`, `"M"` or `"cl A.1"`, `"cl B.1"`):<br>• `"default"`: `"visible"` if no `summarize_row_groups()` follows; `"hidden"` if `summarize_row_groups()` follows (because the content row supplies the label).<br>• `"visible"`: Forces the level label row to appear **even when `summarize_row_groups()` follows** (use *only* when `summarize_row_groups()` emits multiple summary rows or rows that do not serve as the facet header).<br>• `"hidden"`: Suppresses level label rows completely (used when the downstream `analyze()` rows carry the level name, e.g. `AVISIT` in `a_summarize_aval_chg_diff_j`, or single-level filter splits). Does *not* alter tree pathing. |
| **`show_labels`** | `analyze()` | `"default"` *(default)*, `"visible"`, `"hidden"` | **The analyzed variable's label** (`var_labels`, e.g., `"AGE"`):<br>• `"default"`: Hidden when analyzing a single variable alone; visible when analyzing multiple variables (`vars = c("AGE", "BMRKR1")`) or stacking multiple `analyze()` calls.<br>• `"visible"`: Forces the variable label row to appear above the analysis rows.<br>• `"hidden"`: Suppresses the variable label row even in multi-variable or stacked analyses. |

### 4.2 Decision Table for Label & Group Summary Combinations

| Desired Visual Pattern in Shell | `split_rows_by*` Settings | `summarize_row_groups`? | `analyze` Settings |
| :--- | :--- | :--- | :--- |
| **Level label row (empty cells) $\to$ indented leaf rows**<br>`F`<br>`  a   -` | `child_labels = "default"` | No | `show_labels = "default"` |
| **Level summary row (with cells) $\to$ indented leaf rows**<br>`F     -`<br>`  a   -` | `child_labels = "default"` | **Yes** (`cfun` returns 1 row labeled by `labelstr`) | `show_labels = "default"` |
| **Level label row (empty cells) $\to$ indented multi-row group summary $\to$ doubly indented leaf rows**<br>`cl A.1`<br>`  a       -`<br>`  b       -`<br>`    leaf  -` | **`child_labels = "visible"`** | **Yes** (`cfun` returns $\ge 2$ rows or non-header summary rows) | `show_labels = "default"` |
| **Variable header row $\to$ Level rows $\to$ leaf rows**<br>`Sex`<br>`  F`<br>`    a   -` | **`label_pos = "visible"`** | Optional | `show_labels = "hidden"` (if needed) |
| **Top-left corner hierarchy labels**<br>`System Organ Class`<br>`  Preferred Term   all obs`<br>`————————————` | **`label_pos = "topleft"`** on outer split(s) (+ optional `append_topleft("  ...")`) | Optional | `show_labels = "default"` |
| **Leaf rows directly represent split levels (no extra level header)**<br>`SCREENING   -`<br>`BASELINE    -` | **`child_labels = "hidden"`** | No | `afun` labels its row with the split value |

### 4.3 Indentation, Section Dividers, Blank Lines, and Page-By Splits
- **`indent_mod`**: Integer offset passed to `split_rows_by*()`, `summarize_row_groups()`, or `analyze()` (e.g., `indent_mod = -1L` to un-indent a single-level filter split so its summary row aligns with the parent).
- **`section_div` and `top_level_section_div`**:
  - `basic_table(top_level_section_div = "-")` (or `" "`): Inserts a divider line after each top-level row section.
  - `split_rows_by("AEBODSYS", section_div = " ")` (or `"="`, `"~"`): Inserts a divider line after each facet of that row split.
  - `junco::insert_blank_line()`: Inserts an empty spacer row between consecutive `analyze()` calls in a layout pipeline.
- **`page_by = TRUE`**:
  - Passing `page_by = TRUE` to one or more outer `split_rows_by*()` calls declares page-by row splitting (each facet starts a separate logical page with its own page-by header during pagination/export).

## 5. Evaluating & Selecting Row Split Functions (`split_fun`)

By default, sequential `split_rows_by()` calls create a **full-factorial cross-product** of all factor levels defined on each variable. Whenever a table shell deviates from full-factorial partitioning (non-exhaustive levels, non-mutually-exclusive/pooled levels, hierarchically dependent variables, or parent-conditional facets), you must specify a **`split_fun`**.

### 5.1 Built-In Row Split Functions Reference

| Split Function | Category | Behavior & When to Use |
| :--- | :--- | :--- |
| **`drop_split_levels`** | Empirical Exclusion | Drops factor levels that have **zero observations in the incoming parent facet's data**. |
| **`drop_and_remove_levels(excl)`** | Empirical + Prescriptive | Drops unobserved levels **and** prescriptively removes the level names in `excl`. |
| **`keep_split_levels(only)`** | Prescriptive Inclusion | Keeps **only** the factor levels listed in `only` (in that order), even if $N=0$. |
| **`remove_split_levels(excl)`** | Prescriptive Exclusion | Removes the factor levels listed in `excl`, keeping all other declared levels (even if $N=0$). |
| **`reorder_split_levels(neworder, newlabels, drlevels)`** | Prescriptive Reordering | Reorders (and optionally relabels) the split facets to match `neworder`. |
| **`add_overall_level(valname, label, first = TRUE)`** | Non-Mutually Exclusive | Adds a pooled `"All ..."` / `"Any ..."` facet combining all observations at that split tier (placed first if `first = TRUE`, or last if `first = FALSE`). |
| **`add_combo_levels(combodf, trim, first, keep_levels)`** | Non-Mutually Exclusive | Adds virtual combined facets defined by a `data.frame`/`tribble` with columns `valname`, `label`, `levelcombo` (character vector of levels or `select_all_levels`), and `exargs`. |
| **`trim_levels_in_group(inner_var, drop_outlevs = TRUE)`** | Empirical Hierarchical | Placed on the **outer** `split_rows_by()`. For each outer facet, restricts the levels of `inner_var` to only those observed within that outer facet. |
| **`trim_levels_to_map(map)`** | Prescriptive Hierarchical | Restricts valid `(outer_var, inner_var, ...)` combinations to the exact rows of `map` (a `data.frame`/`tribble`), preserving $N=0$ for mapped pairs and omitting unmapped pairs even if observed. |
| **`junco::make_combo_splitfun(nm, label, levels = NULL, rm_other_facets = TRUE)`** | `junco` Combo Helper | Creates a split function that adds a combined facet `nm` (across `levels`, or all levels if `NULL`) and optionally removes the individual level facets (`rm_other_facets = TRUE`). |

---

### 5.2 Critical Pitfall: `drop_split_levels` in Nested Row Hierarchies

> [!WARNING]
> **`drop_split_levels` Evaluates on the Incoming Parent Facet Data!**
> When `drop_split_levels` is used on an **inner** `split_rows_by("SEX", split_fun = drop_split_levels)` nested inside `split_rows_by("RACE", split_fun = drop_split_levels)`, it drops unobserved `SEX` levels **separately inside each `RACE` group**. If `"MULTIPLE"` race only has male subjects in the dataset, `"F"` will disappear under `"MULTIPLE"` while appearing under `"ASIAN"`.
> - **Rule**: If every outer facet must display a uniform, fixed set of inner facets (even when $N=0$ in some subgroups), use **`keep_split_levels(c("F", "M"))`** or **`remove_split_levels(...)`** (or `add_overall_level()`) on the inner split—**never** `drop_split_levels`.
> - Conversely, if the inner variable is **hierarchically dependent** on the outer variable (e.g., `AEBODSYS` $\to$ `AEDECOD` or `REGION1` $\to$ `COUNTRY`, where `"USA"` only belongs to `"North America"`), use **`trim_levels_in_group("AEDECOD")`** on the outer split (empirical) or **`trim_levels_to_map(map)`** (prescriptive).

### 5.3 Continuous, Quantile, and Multi-Variable Row Splits

Not all row facets come from a single categorical column:

1. **Fixed Numeric Cutpoints (`split_rows_by_cuts`)**:
   Splits a continuous variable into disjoint intervals (`cumulative = FALSE`) or cumulative thresholds (`cumulative = TRUE`):
   ```r
   basic_table() |>
     split_rows_by_cuts(
       "AGE",
       cuts = c(0, 35, 50, 100),
       cutlabels = c("<= 35 years", "36 - 50 years", "> 50 years"),
       cumulative = FALSE # Set TRUE for "<= 35", "<= 50", "<= 100"
     ) |>
     summarize_row_groups(cfun = dummy_one_row) |>
     analyze("BMRKR1", afun = dummy_one_row)
   ```
2. **Dynamic / Per-Parent Data-Driven Cutpoints (`split_rows_by_cutfun`)**:
   Computes cutpoints dynamically from the incoming facet's data (e.g., parameter-specific tertiles inside each `PARAMCD` row facet):
   ```r
   param_tertiles <- function(x) {
     qs <- stats::quantile(x, probs = c(1/3, 2/3), na.rm = TRUE)
     cuts <- c(min(x, na.rm = TRUE), qs, max(x, na.rm = TRUE))
     names(cuts) <- c("", "Low", "Medium", "High")
     cuts
   }

   basic_table() |>
     split_rows_by("PARAMCD", split_fun = drop_split_levels) |>
     summarize_row_groups(cfun = dummy_one_row) |>
     split_rows_by_cutfun("AVAL", cutfun = param_tertiles) |>
     analyze("AVAL", afun = dummy_n_rows_factory(2))
   ```
3. **Quartile Row Facets (`split_rows_by_quartiles`)**:
   Splits a numeric variable into 4 quartile buckets (`[min, Q1]`, `(Q1, Q2]`, `(Q2, Q3]`, `(Q3, max]`):
   ```r
   basic_table() |>
     split_rows_by("SEX", split_fun = drop_split_levels) |>
     split_rows_by_quartiles("BMRKR1", split_label = "Biomarker 1 Quartiles") |>
     analyze("AGE", afun = dummy_n_rows_factory(2))
   ```
4. **Multi-Variable Row Splits (`split_rows_by_multivar`)**:
   Creates a row facet for each variable in `vars` (passing the full incoming dataset to each facet while changing the active variable context):
   ```r
   basic_table() |>
     split_rows_by("STRATA1") |>
     split_rows_by_multivar(
       vars = c("AGE", "BMRKR1"),
       varlabels = c("Age (Years)", "Biomarker 1 (ng/mL)")
     ) |>
     analyze("USUBJID", afun = dummy_n_rows_factory(3))
   ```

### 5.4 Composing Custom Row Split Functions (`make_split_fun`)

When a single row split requires multiple behaviors combined (e.g., dropping unobserved levels *and* appending an overall or combo facet, or conditioning facets on `.spl_context`), compose a split function using `make_split_fun(pre = list(...), core_split = ..., post = list(...))`:

#### Pattern 1: Drop Unobserved Inner Levels + Append Inner "All" Subtotal Facet
```r
spl_ctry_all <- make_split_fun(
  pre = list(drop_facet_levels),
  post = list(add_overall_facet("ALL_CTRY", "All Countries in Region"))
)

basic_table() |>
  split_rows_by("REGION1", split_fun = add_overall_level("All Regions", first = TRUE)) |>
  summarize_row_groups(cfun = dummy_one_row) |>
  split_rows_by("COUNTRY", split_fun = spl_ctry_all) |>
  analyze("AGE", afun = dummy_one_row)
```

#### Pattern 2: Parent-Conditional Inner Facets via `.spl_context` (e.g., Dropping `CHG` at `BASELINE`)
Inspect `tail(.spl_context$value, 1)` in a `post` hook to modify inner facets based on the current parent row facet:
```r
drop_cfb_at_baseline <- function(ret, spl, fulldf, .spl_context) {
  parent_visit <- tail(.spl_context$value, 1)
  if (identical(parent_visit, "BASELINE")) {
    ret <- restrict_facets("AVAL", op = "keep")(ret, spl, fulldf)
  }
  ret
}

basic_table() |>
  split_rows_by("AVISIT") |>
  summarize_row_groups(cfun = dummy_one_row) |>
  split_rows_by_multivar(
    vars = c("AVAL", "CHG"),
    varlabels = c("Observed", "Change from Baseline"),
    split_fun = make_split_fun(post = list(drop_cfb_at_baseline))
  ) |>
  analyze("USUBJID", afun = dummy_n_rows_factory(2))
```

#### Pattern 3: Parent-Conditional Combo Level (`add_combo_facet` only under specific parent level)
```r
cond_add_combo <- make_split_fun(
```

```r
top_k_plus_other <- function(k = 3, other_label = "Other System Organ Classes") {
  make_split_fun(post = list(function(ret, spl, fulldf) {
    fac_names <- names(ret$values)
    fac_ns <- vapply(ret$datasplit, NROW, 1L)
    ord <- order(fac_ns, decreasing = TRUE)
    top_names <- fac_names[ord[seq_len(min(k, length(ord)))]]
    rem_names <- setdiff(fac_names, top_names)
    if (length(rem_names) > 0) {
      ret <- add_combo_facet("other", label = other_label, levels = rem_names)(ret, spl, fulldf)
      ret <- restrict_facets(c(top_names, "other"), op = "keep", reorder = TRUE)(ret, spl, fulldf)
    }
    ret
  }))
}

basic_table() |>
  split_rows_by("AEBODSYS", split_fun = top_k_plus_other(k = 3)) |>
  summarize_row_groups("USUBJID", cfun = dummy_one_row) |>
  analyze("AEDECOD", afun = dummy_n_rows_factory(2))
```

## 7. Verification Checklist & Common Row Layout Pitfalls

1. **Every Row Split Chain Must End with `analyze()`**:
   - A `split_rows_by*()` call (even one followed by `summarize_row_groups()`) is **never** a complete leaf. Omitting the terminating `analyze()` produces a degenerate table structure.
2. **Placement of `summarize_row_groups()`**:
   - Always place `summarize_row_groups()` **immediately after** the `split_rows_by*()` whose facets it summarizes, *before* any nested inner `split_rows_by*()` or `analyze()` calls.
3. **Avoid Redundant `child_labels = "visible"` with Single-Row `summarize_row_groups()`**:
   - When `summarize_row_groups()` returns a single summary row representing the facet header, leave `child_labels = "default"` on the preceding `split_rows_by()`. Setting `child_labels = "visible"` will print the facet name twice (once as an empty label row and again on the summary row). Only set `child_labels = "visible"` when `summarize_row_groups()` returns multiple rows (or rows with distinct labels like `"n"`, `"Mean"`) that should be indented *under* the facet label.
4. **Watch for Implicit `nested = FALSE` After `analyze()`**:
   - Every `split_rows_by*()` placed after an `analyze()` automatically resets to the root of the row tree (`nested = FALSE`). If you want the new split to remain inside an outer parent split (e.g., `STRATA1`), use `at_sibling = "<prev_element>"` instead of relying on default post-`analyze` behavior.
5. **Deepest-First Ordering for Multiple `at_sibling` Calls**:
   - When anchoring multiple sibling analyses/splits along the same branch, always order them from the **deepest** anchor to the **shallowest** anchor. Use `get_row_anchor_list(lyt)` to verify eligible anchors.
6. **Duplicate Sibling Names in Row Paths**:
   - If you analyze or split on the same variable more than once at the same nesting level (e.g., `analyze("AGE") |> insert_blank_line() |> analyze("AGE")`), always supply distinct `table_names = "AGE_2"` so row paths remain unique and addressable.
